# Teams 환경안전 Q&A 챗봇 구축 계획 (Copilot Studio 기반)

> 확정된 방향: Microsoft Copilot Studio(노코드) + 기본 제공 생성형 AI 엔진
> 본 문서는 실행 가이드 및 진행 상황 추적용이며, 실제 구축은 Copilot Studio 포털(copilotstudio.microsoft.com)에서 수행합니다. 라이선스/기능 세부사항은 Microsoft 정책 변경에 따라 달라질 수 있으므로, 착수 전 사내 IT/라이선스 담당자 확인이 필요합니다.

## 1. 배경 및 목적

환경안전 실무자가 반복적으로 받는 문의(사내 규정 확인, 법규 해석, SIF 판단기준, 사고 대응 절차 등)를 Teams 챗봇이 1차 응대하여, 응대 시간 절감과 답변 일관성 확보를 목표로 한다.

## 2. 확정된 구축 방향

- **구현 방식**: Microsoft Copilot Studio (노코드 Power Platform)
- **AI 백엔드**: Copilot Studio 기본 제공 생성형 답변 엔진 (별도 API 키 불필요)
- **배포 대상**: 우선 파일럿 범위 확정 필요 (미정 — 3번 항목 참조)

## 3. 착수 전 확인 필요 사항 (확인 필요)

| 항목 | 확인 필요 내용 |
|---|---|
| 라이선스 | 조직의 M365 계약에 Copilot Studio 사용 권한이 포함되어 있는지 (IT/라이선스 담당자 확인) |
| 생성형 AI 기능 활성화 여부 | 테넌트 관리자가 Copilot Studio의 생성형 답변 기능을 허용했는지 |
| Power Platform 환경 | 에이전트를 만들 Power Platform 환경(Environment)에 대한 접근 권한 |
| Teams 배포 승인 | 파일럿 팀 사이드로딩은 별도 승인 없이 가능한 경우가 많으나, 조직 전체 배포(앱 카탈로그 등록)는 Teams 관리자 승인 필요 |
| 데이터 보안 검토 | 지식소스로 사용할 문서에 기밀정보 포함 여부, 보안팀 사전 검토 |
| 지식소스 정리 상태 | 사내 규정/매뉴얼/법령 정리본이 SharePoint 또는 파일 형태로 준비되어 있는지 |

## 4. 단계별 구축 절차

### Phase 0. 요구사항 확정 (착수 전)
- 답변 범위 확정: 사내 규정만 / 외부 법령 포함 / 사고사례 조회 포함 여부
- 파일럿 대상 범위 확정: 특정 사업장·팀 단위 우선 권장
- 지식소스 문서 목록 정리 (5번 표 참조)

### Phase 1. Copilot Studio 에이전트 생성
1. copilotstudio.microsoft.com 접속, 대상 Power Platform 환경 선택
2. 새 에이전트(Agent) 생성, 이름 및 설명 입력 (예: "환경안전 Q&A 도우미")
3. 에이전트의 역할·톤·응답 범위를 안내하는 지침(Instructions) 작성
   - 예: "환경안전 관련 질문에만 답하고, 확인되지 않은 내용은 추정하지 말고 담당자 문의를 안내할 것"

### Phase 2. 지식소스(Knowledge Source) 연결
- SharePoint 사이트/문서 라이브러리, 업로드 파일, 공개 웹사이트(법령 정보 등) 중 선택하여 연결
- 문서별로 최신 개정일자가 명확히 표기되어 있는지 사전 점검 (법령/규정 인용 정확성 확보)

### Phase 3. Topics 및 생성형 답변 설계
- 정형 흐름이 필요한 주제(사고 대응절차 등)는 Topic으로 단계별 대화 흐름 구성
- 단순 지식 검색형 질문은 생성형 답변(지식소스 기반)에 위임
- 5번 표를 초안으로 활용하여 카테고리별 트리거 문구·지식소스 매핑

### Phase 4. 응답 품질 안전장치 설정
- 답변에 출처(citation) 표시 기능 활성화
- 낮은 신뢰도 답변 시 "정확한 확인이 필요합니다. OOO팀에 문의하세요" 형태의 에스컬레이션 문구 지침에 명시
- 법령/규정 인용 시 "본 답변은 OOOO년 O월 개정 기준이며, 최신 여부는 별도 확인이 필요합니다" 등 안내 문구 포함

### Phase 5. 테스트
- 카테고리별 5개 내외, 총 20~30개 테스트 질문 세트 준비 (정답 여부 + 출처 정확성 함께 검증)
- 오탐(엉뚱한 Topic 매칭), 미응답 케이스 점검
- 파일럿 대상자 대상 UAT 1~2주 진행

### Phase 6. Teams 배포
1. Copilot Studio "채널" 메뉴에서 Teams 채널 추가
2. 개인 테스트(사이드로딩)로 담당자 우선 검증
3. 파일럿 팀 대상 배포 (팀에 앱 업로드)
4. 파일럿 결과 반영 후 조직 앱 카탈로그 등록 (Teams 관리자 승인 필요)

### Phase 7. 운영 및 고도화
- 사용자 피드백(👍/👎) 및 미해결 문의 로그 정기 검토
- 지식소스 최신화 프로세스 수립 (규정 개정 시 갱신 담당자 지정)
- 2차 확장: 사고사례 DB 연동, 사업장별 맞춤 답변 등

## 5. Topics / 지식베이스 설계 초안

| 카테고리 | 하위 주제 예시 | 대표 트리거 문구 예시 | 지식소스 유형 | 답변 방식 | 파일럿 우선순위 |
|---|---|---|---|---|---|
| 법규 문의 | 산업안전보건법 등 의무사항 | "중대재해처벌법 적용 대상", "정기 안전점검 주기" | 외부 공개 법령 정리 문서 | 생성형 답변 | 상 |
| 사내 규정 | 안전작업 절차(SOP) | "고소작업 허가 절차", "밀폐공간 작업 기준" | 사내 SOP 문서(SharePoint) | 생성형 답변 | 상 |
| SIF 판단기준 | SIF 분류/판단 프로세스 | "이 사고가 SIF에 해당하나요", "SIF 잠재사고 기준" | 사내 SIF 가이드 문서 | Topic + 생성형 혼합 | 상 |
| 사고 대응절차 | 사고 발생 시 초기 대응 | "화학물질 누출 시 대응 절차", "사고 발생 시 보고 절차" | 사내 비상대응 매뉴얼 | Topic(단계별 안내) | 상 |
| 사고사례 조회 | 유사 과거 사고 검색 | "최근 지게차 사고 사례", "재발방지대책 조회" | 사고 DB (별도 연동 필요) | 생성형 답변 (2차 확장) | 중 |
| 에스컬레이션 | 답변 불가 시 담당자 연결 | "담당자 연결해줘" | - | Topic(Fallback) | 상 |

*본 표는 초안이며, Phase 0에서 확정된 답변 범위에 맞춰 실무자가 조정 필요.*

## 6. 리스크 및 관리 포인트

| 리스크 | 대응 방향 |
|---|---|
| 기밀 문서 포함 시 데이터 노출 우려 | 지식소스 등록 전 보안팀 검토, 접근 권한 있는 문서만 연결 |
| 법령/규정 개정 미반영으로 인한 오답 | 지식소스 정기 갱신 프로세스 및 개정일자 표기 규칙 수립 |
| 환각(hallucination)으로 인한 신뢰도 저하 | 출처 표시 필수화, 낮은 신뢰도 시 에스컬레이션 유도 |
| 조직 배포 승인 지연 | 파일럿 단계에서 Teams 관리자와 사전 협의 |
